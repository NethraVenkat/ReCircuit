customerSchema: fullName trimmed1..100; phone Indian10 digits starting6..9; addressLine trimmed3..300; locality trimmed1..100; pincode exactly6 digits. The UI submits explicit contact details; omitted API customer retains the legacy fictional fallback. No session token is returned or placed in a link/localStorage. RC_SECURE_COOKIE=true enables Secure cookies when serving production over HTTPS; local verification uses HTTP. Origin mismatches are rejected before mutations. A missing origin is allowed for same-cookie CLI/browser test callers.

FileRepository is the actual web adapter. Optional household metadata is a backward-compatible JSON envelope, retained on reads/saves. Explicit null approval now persists (baseline silently preserved old approvals). PostgreSQL schema/adapter are unchanged and are not advertised as supporting the new household metadata. RECIRCUIT_DATA_DIR isolates web repository, browser screenshots, action log and verifier proof files; existing default .data behavior is retained when unset. Unit runs set a unique isolated directory automatically. Locks survive process death; they are deliberately not stolen on a timer. An operator must reconcile any interrupted booking before releasing its lock. This favors no duplicate submission over automatic restart recovery; a durable household job runner remains absent.

Screens: / is the owned list; /arrange is structured intake; /arrange?edit=id edits the same authorized request using expectedHash; /r/[requestId] contains comparison â†’ review â†’ booking/handoff â†’ tracking and native-dialog evidence; /test-cases remains fictional reviewer computation. Journey position is presentation only. No source array replaces discovery in household production planning. The public reviewer endpoint intentionally retains labeled fixture computation.

Precision and identity limits inherited from the domain: row weights remain exact in intake, plan items and booking inputs; pricing.ts rounds its summed load to3 decimals, unchanged. Worker portals normalize item names to canonical labels, so internal row UUID identity is preserved but the independent portal observation cannot prove a vendor-specific original description or a UUID it does not expose. Verification wording is limited to exposed fields. Payout is conditional and shown separately from pickup fees; no real payout or collection is claimed.

No-match discovery persists a zero-leg hashed plan with all rows unrouted. Review remains available; approval rejects zero-leg plans.
