# Boundary contracts

Runtime Zod contracts: `apps/portals/src/lib/geospatial/contracts.ts`. Numbers are finite; missing values are nullable preparation fields, never default zero. Distances metres, durations seconds, loads total-row kg. Service date is a validated calendar date; timezone fixed Asia/Kolkata. Schedule seconds are offsets from local service-date midnight; operating windows may extend beyond 86400 for overnight work. Hard windows constrain **service completion**. Requested text remains a nonbinding preference.

The baseline is stable-ID, first-feasible append insertion across the same vehicles. It remains a candidate. Objective is lexicographic served-count maximum within the search, then directed metres minimum. Alternative deterministic cheapest-insertion orders are bounded. Exact enumeration is restricted to ≤7 pickups and one vehicle; only when full service is feasible and all permutations were visited is **proven-optimum** emitted. Partial service and heuristic failure never prove infeasibility. No unloading, road traffic prediction or independent environmental objective is modelled. The independent validator separately replays every directed edge, cumulative pickup load, waiting/service time and window, checks totals and conservation, and rejects invented vehicle/stop identities.

Provider adapter status: OSRM table adapter IMPLEMENTED, offline-mock tested; **NOT VERIFIED LIVE**. Synthetic providers only resolve registered inputs. No public geocoding/tiles or road demo endpoints are enabled. No real addresses have been transmitted.

Fuel/emissions are intentionally absent until explicit applicable factor provenance and vehicle fuel assumptions are available. No measured environmental outcome is implied by a planned distance difference.
