# Operator guide and local release preparation

This is a local, authenticated, map-independent operational **planning preview**. It is not dispatch, collection confirmation or a production-ready shared fleet service. The current default is a closed synthetic graph. Live HeiGIT public-location adapter verification is separate from a live customer routing workflow.

## Run and recover locally

From the isolated worktree, the executed installation was `npm.cmd ci --ignore-scripts --offline --no-audit --no-fund`. Shared package compilation: `node node_modules/typescript/bin/tsc --build packages/llm packages/core packages/db`.

1. Configure a new absolute synthetic seed directory through `ROUTING_SYNTHETIC_SEED_DIR` and run `node node_modules/vitest/vitest.mjs run apps/portals/src/lib/geospatial/seed.test.ts`. The seed uses exclusive file creation and refuses to overwrite an existing run. It creates `portal`, `household` and `scenario.json` beneath that directory. These are explicitly fictional bookings and verification records, not historical customer evidence.
2. Set `ROUTING_TEST_DATA_DIR` to that directory and supply `ADMIN_TOKEN` privately. Optionally set `ROUTING_ENV_FILE` to the existing ignored provider env file. Do not copy keys into commands, source files or screenshots.
3. Run `node scripts/start-routing-preview.mjs`. The executed launcher serves `http://127.0.0.1:3200/admin/routing`, checks that 3200 is available, binds loopback only, loads only the two authorized provider variables, isolates booking/planning storage, and keeps MapTiler browser exposure disabled. It normalizes CR-only env-file line endings in memory without editing the env file. Use the current process's stop signal, or the optional `ROUTING_STOP_FILE` marker, to stop only this preview.
4. Enter the operator token and explicit service date. Reading does not generate. Review exclusions before proceeding. Coordinates require an explicit human review and versioned service-duration assumption. No city-centre fallback or LLM geolocation exists.
5. Add/select planning vehicles using the structured fleet/depot form. Enter total kg capacity, initial kg load, compatible material categories, explicit operating times and depot coordinates/source. The simple editor returns to the same depot; the expandable advanced configuration supports distinct start/end depots. No unloading is inferred.
6. Generate explicitly. Read numbered proposed stops, arrival/service times, cumulative load and requested versus confirmed windows. Schematic dashed connectors are not driving directions. The accessible ordered list is authoritative even if maps fail.
7. Reload and re-enter the token; select proposal history. A changed source booking, coordinate, service assumption, fleet configuration or expired matrix makes the prior proposal stale. Old versions remain immutable. Recalculate with a new idempotency key after checking exclusions; retrying the same key returns the same proposal only for unchanged sources.

The default synthetic matrix resolves only the registered fictional grid and stable node identities. Changing coordinates to arbitrary real locations must fail rather than fabricate a successful matrix. For controlled live adapter work the runtime supports a separately enabled public-documentation-coordinate provider; it rejects other node identities/coordinates and limits requests. No real customer addresses or coordinates are authorized for external transmission.

## Environment variable names (no credential values)

| Names | Convention / role |
|---|---|
| `HEIGIT_API_KEY` | Server-only. Authorization header to fixed current HeiGIT HTTPS API. Never `NEXT_PUBLIC_`, never sent in a browser response. |
| `MAPTILER_API_KEY` | Loaded server-side; intentional public browser delivery is gated behind verified provider settings and exact permitted origin. Current launcher always disables that delivery. |
| `MAPTILER_ALLOWED_ORIGINS` | Exact application origins; authorized local origins are `http://localhost:3200` and `http://127.0.0.1:3200`. No wildcards or guessed production hosts. |
| `MAPTILER_ORIGIN_RESTRICTIONS_VERIFIED` | Must remain disabled until actual provider account settings and permitted/unpermitted browser-origin behaviour are verified. A generic HTTP 200 does not prove enforcement. |
| `ROUTING_ENABLED`, `ADMIN_TOKEN`, `RECYCLER_ID`, `ROUTING_ALLOWED_ORIGINS` | Feature/authentication and fixed-tenant/CSRF configuration. Only explicit header token is accepted for routing. No query-token authentication. |
| `RECIRCUIT_PERSISTENCE`, `STORAGE_DIR`, `ROUTING_DATA_DIR`, `ROUTING_HOUSEHOLD_EVIDENCE_DIR` | Local source booking, immutable proposal and read-only household evidence locations. Do not point the preview at unrelated or production data. |
| `ROUTING_TEST_DATA_DIR`, `ROUTING_SYNTHETIC_SEED_DIR`, `ROUTING_ENV_FILE`, `ROUTING_STOP_FILE` | Reproducible isolated preview setup and owned-process shutdown. |
| `ROUTING_MATRIX_PROVIDER`, `ROUTING_EXTERNAL_PUBLIC_ENABLED` | Separate explicit public-only HeiGIT runtime opt-in; default synthetic mode makes no external provider calls. |
| `ROUTING_LIVE_PUBLIC_TEST`, `ROUTING_LIVE_EVIDENCE_DIR`, `ROUTING_MAPTILER_PROBE`, `ROUTING_BENCHMARK_DIR` | Non-default controlled test/measurement switches; not production configuration. |

MapTiler is not globally inlined through a `NEXT_PUBLIC_` variable. The designed browser boundary is a runtime, authorized, no-store configuration response only after restriction verification. No actual key has crossed that boundary. The current renderer intentionally uses the independent schematic/road-geometry SVG and stop list; MapTiler tile rendering remains blocked.

## Provider selection, quotas, privacy and attribution

Accessed official sources on 2026-10-23/24:

- [HeiGIT current API migration notice](https://ask.openrouteservice.org/t/deprecating-api-openrouteservice-org-in-favour-of-api-heigit-org/7912) and [HeiGIT announcement](https://heigit.org/changes-in-the-openrouteservice-universe/): use `api.heigit.org/openrouteservice/v2`, not the deprecated hostname. Two initial authorized requests hit the old origin before the current notice was discovered; the replacement origin was subsequently verified separately. Both observations are retained.
- [ORS matrix contract](https://giscience.github.io/openrouteservice/api-reference/endpoints/matrix/): longitude/latitude ordering, seconds and explicit distance units, directed source/destination positions. Hosted adapter requests metres and driving-car, maximum ten nodes per generation, at most four configured HTTP attempts (runtime public preview caps two), no automatic retries. A 429 requires later explicit retry; it never becomes a zero edge.
- [OSRM v26.5 HTTP API](https://project-osrm.org/docs/v26.5.0/http): private allowlisted origin, 16×16 blocks, sequential concurrency, at most two attempts per block and five-second timeout. Fallback-generated distances are rejected; null unreachable pairs remain unreachable. Logical element count and attempted elements (including retries) are tracked separately. For 64 nodes the maximum is 16 blocks × two attempts; the matrix has 4096 logical pairs. This is not a dollar-price quote.
- [Google Routes matrix](https://developers.google.com/maps/documentation/routes/compute_route_matrix) and [billing](https://developers.google.com/maps/documentation/routes/usage-and-billing): a viable managed alternative but billed by origin×destination elements; no Google API or paid operation was enabled. Quotas, commercial retention and display restrictions require the selected provider's current agreement, not assumptions copied from OSM.
- [Public Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/): public use has identification/attribution/rate constraints and is not enabled for private customer addresses. Manual reviewed coordinates and closed-world synthetic lookup require no geocoder transmission. No public geocoding success is claimed.
- [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/): hosted tiles have operational rules and no SLA; no public tile requests are enabled. OSM data availability is not unlimited hosted service permission.
- [MapTiler key restrictions](https://docs.maptiler.com/guides/developer/credentials/api-key/) and [management API](https://docs.maptiler.com/cloud/admin-api/api-keys/): account-origin settings are separate from a data API key. Documentation describes host-based origin settings; exact port granularity must be established through actual browser tests rather than assumed. No management/dashboard session was available. Local application gating is exact-origin, but provider account enforcement remains BLOCKED. No production origin was enabled.

No customer data was transmitted. Authorized live probes used two public coordinates from ORS documentation. Total measured probes: four HeiGIT requests (two 2×2 matrices = eight logical elements, plus two geometry queries across old/current API origins) and one MapTiler style-metadata request. No paid feature, plan upgrade or extra quota was requested. Billing/account plan itself was not inspected; no monetary saving or invoice result is claimed. The local request budget is a safety bound, not proof of an account's billing terms.

Provider caches are tenant/input/profile/origin isolated and memory-only. Private OSRM cache is bounded to 128 entries and at most one hour; HeiGIT cache to 32 entries and five minutes. Source/address/provider changes miss the cache. Matrix snapshots and calculation provenance are retained in local proposal history; before real customer or commercial use, review the applicable provider's result-storage, attribution, privacy/retention and downstream licensing terms. Never persist MapTiler style responses with credential-bearing URLs. Road geometry carries explicit HeiGIT/OSM attribution. Synthetic geometry is clearly fictional and has no basemap attribution claim.

## Security, storage compatibility and recovery

The routing service receives a read-only booking source interface. It cannot call approval, booking submission, scheduling, fee, data-wipe, OTP or collection mutation methods. Both household approval/verified-leg evidence and matching portal data are required. Missing or stale verification, unknown loads/materials, or unsupported dispatcher time strings are exclusions. Header authentication precedes source access; tenant is fixed server-side and object IDs are checked. Mutations require exact configured origin plus actual Host, independent of untrusted forwarded headers. Bodies are streamed with a 64 KiB bound. Errors omit keys, addresses and raw provider response bodies.

Proposal/configuration files live under a separate absolute routing root, tenant partition and numeric version. Exclusive creation prevents overwriting historical versions. One in-process tenant operation runs at once; a second returns busy, and generation rechecks sources before saving and on read. Idempotent retries return the old proposal or a conflict; changed sources are never silently treated as current. Failed provider results are not persisted as valid routes. Invalid saved schemas, totals or constraints are rejected. Proposal history is not operational dispatch history.

No booking schema migration was needed for this local integration. Existing booking JSON and household records are read without adding fields. **Production routing intentionally fails closed**: the current repository's development-file conventions are used, not an invented durable multi-worker production store. Distributed persistence/locking, production operator identity and private-address/provider governance remain unsupported and must be implemented/reviewed before production activation. This is a local preview release, not a claim that simply flipping a production flag is safe.

If a calculation fails: inspect exclusions, current source and retained failure output; do not resubmit a booking. For expired matrix evidence explicitly regenerate. For stale proposal read old immutable evidence and generate a new version only after review. For unavailable map/geometry use the ordered list. A material geometry/matrix mismatch is disclosed; the proposal is never dispatch-ready.

## Estimate methodology

Baseline and candidate share pickups, vehicles, depots, directed matrix and constraints. Stable-ID feasible insertion remains a candidate. No percentage is shown for a zero baseline; unequal served scopes suppress a headline reduction, and negative improvements retain their sign. Regenerated versions are compared individually, never summed into cumulative savings.

No applicable sourced fuel rate/emission factor was available, so the UI omits both. If later introduced, version source/year/geography/fuel/units/scope and distinguish tailpipe CO2 from lifecycle CO2e. The formulas would be `fuel_litres = distance_km × litres_per_100km / 100` and `emissions_kg = fuel_litres × applicable_kg_per_litre`. Constant factors are rescalings of distance, not three independent optimizer achievements. Never call these measured fuel, emissions saved or distance driven.
